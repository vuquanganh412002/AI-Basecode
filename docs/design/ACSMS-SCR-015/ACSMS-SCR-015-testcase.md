## システム概要

本システムは、JA向けのクラウド型読者管理システムであり、購読者情報の管理、購読履歴の管理、口座振替データの管理などの機能を提供する。本画面は、検索した購読者を複数選択し、配達販売店を一括で置換する機能を提供する。

- 各テストケースに観点ID（観点一覧参照）を付与する。

  - ・ACSMS-TC-015-049 と同じデータ（販売店A 3件・販売店B 2件・販売店C 2件）

### 手順

ステップ1：
検索エリアの「配達販売店」のラベルと必須マークの有無を確認する

ステップ2：
配達販売店を**未指定**のまま、購読種別=紙版・適用日=2030/09/01・置換先配達販売店=販売店B で検索する

ステップ3：
配達販売店=販売店A を指定して同じ条件で検索し、ステップ2との差分を確認する

ステップ4：
配達販売店を未指定のまま検索した結果を全選択して置換を実行する

### 期待結果

ステップ1：
ラベルが「配達販売店」（「置換元配達販売店」ではない）であり、必須マーク（`*`）が付いていないこと（顧客要件2026-07 改訂で必須→任意へ戻した）

ステップ2：
販売店A の 3 件と販売店C の 2 件、計 5 件が表示されること（置換先=販売店B 以外の全販売店が対象）。販売店B の 2 件は除外されること

ステップ3：
販売店A の 3 件のみが表示されること（`eff.hanbaiten_id = :hanbaiten_id` が追加で効く）

ステップ4：
販売店A・販売店C の購読者がまとめて販売店B へ置換されること

補足：
・配達販売店は「指定時のみ絞り込む」条件。未指定でも `≠ 置換先` は常に適用されるため、置換先を配達中の購読者が混入することはない（API設計書 v1.8・§4.3）
・複数の置換元から1つの置換先へまとめる運用のための改訂。必須のままでは販売店ごとに検索・置換を繰り返す必要があった
