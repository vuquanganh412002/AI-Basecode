### B. 機能詳細


#### 1. 画面初期表示

- **1.1** 増減連絡票（販売店）出力画面にアクセスすると、デフォルトで以下のように表示
  - 出力条件フォーム
  - 適用日：未選択
  - 販売店：未選択
  - 管理支店：未選択
  - プレビューエリア：空
- **1.2** 権限チェック：
  - 日農 管理者 / 日農 担当者 → ACSMS-MSG-028-001 を表示。アクセス不可
  - 中央会：自中央会分のみ出力可
  - JA本店：自JAの管理支店分のみ出力可
  - JA管理支店 → 自アカウントのkanri_shiten_idに属するデータのみ出力可
- **1.3** プルダウンリスト：
  - 販売店：m_hanbaitenから取得。電子版ダミー販売店は非表示（廃店（haiten_flg = true）の販売店を除外）
  - 管理支店：m_kanri_shitenから取得。JA支店は自支店のみ表示

#### 2. レポートプレビュー

- **2.0** 出力条件の販売店／管理支店は**複数選択ドロップダウン**（チェックボックスから変更）：
  - 販売店コード／名称（管理支店も同様）で**部分一致検索**（BE で `code ILIKE OR name ILIKE`）。
  - **50件ずつ**ロードし、ポップアップを下端までスクロールすると次ページを追加取得（無限スクロール）。
  - 複数選択可・未選択＝全件。共通プルダウンAPI（`GET /api/v1/hanbaiten/dropdown`・
    `GET /api/v1/kanri-shiten/dropdown`）に `q` / `page` / `per_page` / `match_field`（既定
    both＝コードOR名称）を付与。ページングは page 指定時のみ（未指定は従来どおり全件）。
- **2.1** データ取得ロジック：
  - t_dokusya_rireki テーブルからレコードを抽出
  - 販売店が選択されている場合（全てでない場合）、該当販売店でフィルタリング。未選択の場合、全ての販売店を取得
  - 管理支店が選択されている場合（全てでない場合）、該当管理支店でフィルタリング。未選択の場合、全ての管理支店を取得
  - 適用日：必須項目、入力しない場合：ACSMS-MSG-028-004メッセージを表示。入力した場合：データの変更適用日 =　画面の適用日　かつ　増減報告フラグが1のものを抽出
  - JA管理支店権限の場合 → kanri_shiten_id の条件を追加
- **2.2** グループ化と並び順：
  - 販売店 + 管理支店の組み合わせでグループ化
  - 各組み合わせごとに1帳票ブロックを作成（物理ページの区切りは2.3のページ送り＝15購読者単位を参照。1ページに複数組み合わせが載る/1組み合わせが複数ページにまたがる場合がある）
  - 帳票は販売店コードの昇順で作成
- **2.3** 結果表示：
  - 3つのテーブル（増部 / 減部 / 住所変更）をプレビューエリアに表示
  - **同一購読者の同日複数履歴は累計する**：その日に複数回変更がある場合（例 1→3→5）は
    日初（その日の最小履歴番号の前回値）→ 日末（その日の最大履歴番号の現在値）で
    1件にまとめる（1→3→5 は 1→5、解約 …→0 は減として反映）
  - 累計後、各購読者を以下の条件で各テーブルに振り分ける
  - [販売店変更]（前回販売店 ≠ 現販売店）
  - 前回販売店と販売店を比較し、変わっていれば旧販売店に「減（前回部数）」、新販売店に「増（現部数）」で反映
  - [増部]（同一販売店）
  - net（現部数 − 前回部数）> 0
  - [減部]（同一販売店）
  - net（現部数 − 前回部数）< 0
  - [住所変更]
  - 前回の配達先住所と現在の配達先住所が異なる（前回住所 ≠ 現住所）
  - ただし前回住所が空（初回履歴）の場合は住所変更に出さない
  - レポートの表示順序と、項目がない場合の表示方法：①すべての項目を昇順で表示します。②昇順で項目がなくなったら、降順で表示します。③降順で項目がなくなったら、住所が変更された項目を表示します。いずれかのカテゴリに項目が0の場合は、タイトルと空白行を表示します。
  - **ページ送り（SQL OFFSET/LIMIT・購読者単位）**：1ページ=A4 1枚＝既定15購読者（≒15レコード。大半1レコード/購読者）。累計は同日履歴をまたいで分割できないため、ページングの最小単位は購読者（`dokusya_id`）。ページャでページ移動するたびに当該ページを別APIで再取得し、BEは1ページ分の購読者の明細だけをロードする（ブラウザも1ページ分のみ描画）。`増減報告フラグ=1 かつ 変更適用日=適用日` の抽出条件は維持（同日変動のみ）。
  - 帳票ヘッダ：ページ数を表示：Page: 現在ページ/全体数
  - TELとFAXは管理支店の情報を表示
  - 住所変更テーブルは1購読者につき2行（変更前 / 変更後）で表示
  - **発行日時**：プレビュー押下時刻（JST `YYYY/MM/DD HH:mm`）を条件エリアのラベルに表示し、各帳票フッタの**右下**に「発行日時：YYYY/MM/DD HH:mm」を印字する（例：発行日時：2026/06/25 10:58）
- **2.4** 対象データなしの場合 → ACSMS-MSG-028-002 を表示
- **2.5** システムエラーの場合 → ACSMS-MSG-028-003 を表示

#### 3. 電子帳票作成

- **3.1** 「電子帳票作成」ボタンをクリックすると、2.1と同様のデータ取得を実施
- **3.2** データが有効な場合、電子帳票ファイルを生成：（ファイルのテンプレートはまだ共有していただいないため、ご共有いただいた後に更新があれば追記させていただく）
  - 出力形式：PDF
  - **改ページはプレビューと同一**：1ページ=15購読者（購読者を販売店コード昇順・dokusya_id昇順に並べ15人ずつ）。1ページに複数販売店が載る場合は各販売店ブロックを続けて積み、ページ先頭でのみ改ページ。Page表記は「ページ番号/総ページ数」。PDF の n ページ目 = プレビューの n ページ目
  - **発行日時**：全ページのフッタ右寄せに「発行日時：YYYY/MM/DD HH:mm」を印字する。値はプレビュー押下時刻（出力APIの `issued_at` で受け取る。未連携時は出力押下時刻）
  - 出力後の処理：S3に保存
  - **ファイル名（出力アカウントのロール別・顧客要件2026-07）**：
    - JA本店アカウントが出力した場合：`増減連絡票_{JA名}_{JAコード}_{適用日（YYYYMMDD）}.pdf`
    - JA管理支店アカウントが出力した場合：`増減連絡票_{JA名}_{JAコード}_{管理支店名}_{管理支店コード}_{適用日（YYYYMMDD）}.pdf`
    - 中央会アカウントは複数管理支店にまたがるため、JA本店と同一形式（管理支店を含めない）とする。
    - ダウンロード表示名（直接ダウンロード／ファイル管理画面とも）は上記のタイムスタンプ無し名。S3保管上のオブジェクト名は再出力時の上書き防止のため別途タイムスタンプを付与して一意化する。
- **3.3** 対象データなしの場合 → ファイルは出力しない。ACSMS-MSG-028-002 を表示
- **3.4** システムエラーの場合 → ACSMS-MSG-028-003 を表示
