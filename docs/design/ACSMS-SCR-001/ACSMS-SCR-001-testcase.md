## システム概要

本システムは、JA向けのクラウド型読者管理システムであり、
購読者情報の管理、購読履歴の管理、口座振替データの管理などの機能を提供する。
主な機能として、購読者情報の登録・更新・検索、
購読内容の変更履歴管理、口座振替データの作成および管理、
ファイルのアップロード・ダウンロード機能、システムのお知らせ管理などを提供する。
また、ユーザーのログイン管理、ログイン履歴の記録、
ユーザー操作ログの記録などのセキュリティ・監査機能をサポートする。

## ACSMS-TC-001-001 — NICHINO_ADMIN ログイン — MFA不要パス

- **観点ID**: VP-A-01
- **種類**: Normal (正常)
- **前提条件**:
  - ・テストアカウント role: NICHINO_ADMIN
  - ・mfa_enable_flg = false
  - ・account_lock_flg = false
  - ・login_failure_count = 0

### 手順

ステップ1：
ブラウザで `/login` にアクセス、フォームに有効なユーザーIDとパスワードを入力

ステップ2：
ログインボタンをクリック

ステップ3：
DevToolsのNetworkタブで POST `/api/v1/auth/login` のレスポンスを確認

ステップ4：
DevToolsのApplicationタブで Cookie `session_id` を確認

ステップ5：
DBで以下クエリを実行
```sql
SELECT login_result, account_id, login_id, failure_reason
FROM t_login_log
WHERE login_id = :login_id
ORDER BY login_datetime DESC
LIMIT 1;
```

### 期待結果

ステップ1：
ログインフォームが表示される、IDとパスワード欄が空、エラーなし

ステップ2：
処理中はログインボタンが無効化される

ステップ3：
HTTPステータスコード：200
レスポンス：`data.mfa_required = false`、`data.user` にユーザー情報
`data.user.role_code = 'NICHINO_ADMIN'`、`data.user.ja_id = null`、`data.user.kanri_shiten_id = null`
`data.user.permissions` に `dokusya.*`、`hanbaiten.*`、`tanka.*`、`account.*`、`oshirase.*`、`log.view` を含む

ステップ4：
Cookie `session_id` が HttpOnly + Secure + SameSite=Strict 属性で設定される
Max-Age = 86400（24時間）

ステップ5：
1行、`login_result = 1`（成功）、`failure_reason` が空、`account_id` がテストアカウントと一致

補足：
・ログイン成功後トースト「ログインしました。」表示、メイン画面（/dashboard）へ遷移
・セッションが Redis に保存される（キー：session:{session_id}、TTL 24時間）
