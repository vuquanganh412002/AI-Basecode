## システム概要

本システムは、JA向けのクラウド型読者管理システムであり、
購読者情報の管理、購読履歴の管理、口座振替データの管理などの機能を提供する。
主な機能として、購読者情報の登録・更新・検索、
購読内容の変更履歴管理、口座振替データの作成および管理、
ファイルのアップロード・ダウンロード機能、システムのお知らせ管理などを提供する。
また、ユーザーのログイン管理、ログイン履歴の記録、
ユーザー操作ログの記録などのセキュリティ・監査機能をサポートする。

- 優先度（P0：リリース阻害／P1：高／P2：中）を設定する。

## ACSMS-TC-012-001 — NICHINO_ADMIN — パスワード再設定フロー全体利用可

- **観点ID**: VP-A-01
- **種類**: Normal (正常)
- **前提条件**:
  - ・テストアカウント role: NICHINO_ADMIN
  - ・有効なメールアドレス設定済
  - ・本画面は認証不要（ログイン前ユーザーが利用）

### 手順

ステップ1：
ブラウザで `/forgot-password` にアクセス、メールアドレスを入力 → 送信

ステップ2：
受信メールから再設定リンクをクリック、`/reset-password?token=xxx` に遷移

ステップ3：
新しいパスワードと確認用パスワードを入力 → 「パスワードを更新する」ボタン押下

ステップ4：
3秒後 `/login` 画面で新しいパスワードで再ログイン

### 期待結果

ステップ1：
HTTPステータスコード：200
レスポンス：`message` 「パスワード再設定用のメールを送信しました。メールを確認してください。」
フォーム非表示、成功メッセージ表示

ステップ2：
トークン検証成功、パスワード変更フォームが表示される

ステップ3：
HTTPステータスコード：200
トースト「パスワードを更新しました。ログイン画面に移動します。」表示
3秒後にログイン画面へ自動遷移

ステップ4：
新しいパスワードでログイン成功

補足：
・`m_account.password_hash` 更新、`password_updated_at` が現在時刻
・`t_mfa_otp.used_flg = true` （トークン無効化）
・`t_log` に operation='PASSWORD_RESET'、result_status=1 のログ記録
・実装：パスワード更新成功後、Redisセッション全削除（`destroyAllForAccount`）

## ACSMS-TC-012-003 — CHUOKAI — パスワード更新後の全セッション無効化

- **観点ID**: VP-A-05
- **種類**: Normal (正常)
- **前提条件**:
  - ・テストアカウント role: CHUOKAI
  - ・複数のブラウザでログイン済（ブラウザA、ブラウザB）
  - ・両方の Cookie に有効なセッションあり

### 手順

ステップ1：
別のブラウザCで `/forgot-password` → 再設定リンク → パスワード更新

ステップ2：
ブラウザA・ブラウザB それぞれで API リクエスト（例：GET `/api/v1/dokusya`）を送信

ステップ3：
Redis セッションを確認：
```
KEYS session:*
SMEMBERS account_sessions:{account_id}
```

### 期待結果

ステップ1：
パスワード更新成功

ステップ2：
両方とも HTTPステータスコード：401
error_code：UNAUTHORIZED
message：「セッションが切れました。再度ログインしてください。」
フロントエンド側で `/login` へ自動遷移

ステップ3：
当該 account_id に紐づくセッションがすべて削除されている
`account_sessions:{account_id}` Set も削除されている

補足：
・実装：`AuthService.resetPassword` 内で `destroyAllForAccount(accountId)` 呼び出し
・トランザクション外で実行（Redisエラーがパスワード更新をロールバックしないため）
・Cookieが盗まれた攻撃者が継続利用できない設計
