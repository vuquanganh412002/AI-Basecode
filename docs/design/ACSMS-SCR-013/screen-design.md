### B. 機能詳細


#### 1. 画面初期表示

- **1.1** 画面表示時に購読者ID（dokusya_id）を受け取り、対象の履歴データを取得する。取得した履歴データを一覧形式で表示する（中央会：自中央会のみ選択可。（管轄JAの読者は見れない）JA本店：自JAのみ選択可。JA管理支店：自管理支店のみ選択可）。
- **1.2** 対象IDのレコードについて、履歴番号を降順でデータを並べ、最新のレコードを先頭に表示する。
- **1.3** ・データなしの場合　→　ACSMS-MSG-013-001を表示する。
  - ・システムエラーの場合　→　ACSMS-MSG-013-002を表示する。

#### 2. 戻る操作

- **2.1** 「前の画面に戻る」ボタンを押下すると、確認ダイアログ無しで購読者情報登録画面に戻る。

#### 3. ページネーション

- **3.1** 履歴一覧はページネーションされ、別のページを押下すると、そのページのデータを取得して表示する。

#### 4. 履歴取消（「取消」ボタンの活性条件・顧客要件2026-07）

- **4.1** 「取消」ボタンは全行に表示するが、取消可能な行（下記すべてを満たす）でのみ活性化する。取消不可の行は非活性（BE の `can_torikeshi` フラグで判定）。`dokusya.update` 権限が無い場合は全行非活性。
- **4.2** 取消可能条件（すべて満たす行のみ）:
  1. **紙版のみ**（`dokusya_shubetsu=1`）。電子版(2)・併読(3)は電子版読者管理システムへ即時連携されるため取消不可。
  2. 新規でない（`shinki_flg=false`）。※解約→再購読も新規フラグのため不可。
  3. 取消済でない（`torikeshi_flg=false`）。取消の取消は不可。
  4. **適用日が未来**（本日 < `joho_henko_tekiyo_date`、JST）。適用日到来済み（反映・報告済み）は取消不可。※紙版の解約行は `joho_henko_tekiyo_date = 購読中止日` のため「解約バッチ（中止日）到来前まで取消可＝解約の取り止め」もこの条件で満たす。
  5. **適用日チェーンの末尾**（有効レコード）。判定は `rireki_no` 最大ではなく、`torikeshi_flg=false` の行のうち（適用日最大・同日 `rireki_no` 最大）で行う。後続に未取消行がある中間レコードは不可（LIFO・末尾から順に）。
- **4.3** レコード種別別の取消可否:

  | レコード種別 | 取消可否 | 条件・備考 |
  | --- | --- | --- |
  | 新規（履歴No1） | 不可 | 前回状態が無く打ち消せない。訂正は解約＋新規登録。 |
  | 再購読レコード | 不可 | 初回購読開始日の書き換えを伴い継続。 |
  | 取消済・打ち消し（`torikeshi_flg=1`） | 不可 | 取消の取消は不可。 |
  | 中間レコード（後続に未取消あり） | 不可 | LIFO（末尾から順に）。 |
  | 適用日到来済み（適用日 ≤ 本日） | 不可 | 既に反映・報告済み。訂正は未来日で調整報告。 |
  | 電子版・併読 | 不可 | 電子版連携のため取消不可（紙版のみ可）。 |
  | 解約予定（購読中止日設定済み・バッチ未処理・紙版） | 可 | 中止日到来前まで取消可＝取り止め。電子版は中止日設定と同時に連携済みのため不可。 |
  | 通常変更（紙版・末尾・適用日未来：増減・住所・販売店・氏名 等） | 可 | 末尾かつ適用日未来の紙版のみ可。 |

- **4.4** 取消不可の行に対して取消 API を呼んだ場合、BE は HTTP 400 `TORIKESHI_NOT_ALLOWED` を返す。該当メッセージは ACSMS-MSG-013-006。
- **4.5** 「取消」ボタン押下時は確認ダイアログ（タイトル「履歴の取消（赤伝）」・実行ボタン「取消する」）を開き、**取消理由（必須・500文字以内）**の入力を求める。未入力なら ACSMS-MSG-013-004、超過なら ACSMS-MSG-013-005 を表示し、API を呼ばない（BE の DTO と同一ルールを FE でも検証する）。
- **4.6** 取消成功時は ACSMS-MSG-013-003 をトースト表示し、一覧を再読み込みする。取消理由は対象行・打ち消し行の備考、および操作ログ（`t_log`）の3か所に記録される。
  - ・デフォルト：20件/ページ
  - ・最大：100件/ページ
