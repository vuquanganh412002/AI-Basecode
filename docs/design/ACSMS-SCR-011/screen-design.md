### B. 機能詳細


#### 1. 画面初期表示

- **1.1** 紙版購読者の新規作成・更新フォーム。
- **1.2** 中央会：自中央会のみ選択可。（管轄JAの読者は見れない）JA本店：自JAのみ選択可。JA管理支店：自管理支店のみ選択可。※電子版クレカ決済者・併読者は編集・削除不可。
  - denshi_shonin_status = 0の場合、JAが登録可能、編集不可
- **2.0** 購読者登録
- **2.1** クライアント側のデータチェックを実行（必須項目、フォーマット、相関チェックを行う）
- **2.2** エラーがある場合→入力エラーの場合、エラーとなっている項目の下に該当メッセージ（ACSMS-MSG-011-001〜ACSMS-MSG-011-010）を表示
- **2.3** 必須項目を入力しない場合、ACSMS-MSG-011-013メッセージを表示
- **2.4** API POST /api/subscribersを呼び出す
- **2.5** サーバー側でバリデーション、マスタ存在チェック、メール重複チェック
- **2.6** t_dokusya + t_dokusya_rirekiを1トランザクションで作成
- **2.7** 登録成功の場合→ACSMS-MSG-011-011を表示→/readersへリダイレクト
- **2.8** システムエラーの場合、ACSMS-MSG-011-012を表示
- **3.0** 電子版承認
- **3.1** 条件：denshi_shonin_status = 0（未承認）
- **3.2** 本システム ← 電子版購読者管理システム：Web申込読者情報の受信・承認（電子版連携は10分ごとの自動更新である）
- **3.3** 「承認」ボタンを押下すると、APIがdenshi_shonin_status = 1（承認済み）に設定、  新規履歴レコードを作成
- **3.4** 本システム → 電子版：承認済み読者情報の反映・口座振替申込の連携
- **4.0** 電子版否認
- **4.1** denshi_shonin_status = 0の場合のみ「承認しない」ボタンを表示
  - 本システム ← 電子版購読者管理システム：Web申込読者情報の受信・承認
- **4.2** 「承認しない」ボタンを押下すると、否認確認ダイアログ（ACSMS-MSG-011-014）を表示
- **4.3** 「はい」ボタンを押下する場合、API PUT /api/subscribers/:id/rejectを呼び出し、  denshi_shonin_status = 2（否認）に設定、  新規履歴レコードを作成
  - 電子版否認成功の場合→/readersへリダイレクト
  - システムエラーの場合→ACSMS-MSG-011-012を表示
- **4.4** 「いいえ」ボタンを押下する場合、何も行わず、現在の画面を維持
- **5.0** 履歴表示
- **5.1** API GET /api/subscribers/:id/historyを呼び出し
- **5.2** 履歴一覧モーダルを表示、rireki_no降順で並べ替え
- **5.3** 表示項目：履歴No、作成日、手続種類、変更理由
- **6.0** 販売店検索
- **6.1** ポップアップを開き、ログイン中JA同一の販売店のみ表示
- **6.2** 対象販売店を選択すると、No.38（コード）とNo.39（名称）に自動入力
- **7.0** 購読種別及び支払方法による表示切替
- **7.1** 購読種別=電子版/併読時 →メールアドレス（No.22）が必須
- **7.2** 紙版: 開始日(No.52)=カレンダー, 中止日(No.53)=カレンダー, 請求開始月(No.55)=非表示
- **7.3** 電子版（JA口振）：開始日=ラジオボタン(今日/翌月1日)、中止日=「X月末で終了」、請求開始月=ラベル読取専用(電子版連携)
- **7.4** 電子版（クレカ）/併読: 開始日=読取専用(電子版連携), 中止日=読取専用(電子版連携), 請求開始月=ラベル読取専用(電子版連携)
- **7.5** 購読種別が「電子版」または「併読」の場合、配達先情報エリアを非活性化（入力不要）
- **7.6** 「請求開始月」: 電子版または併読の場合のみ表示する条件を追加
- **8.0** 手続種類変更
- **8.1** 解約を選んで登録する場合：問答無用で購読部数を0にし、kaiyaku_flg=TRUE
- **8.2** 新規を選んで登録する場合：通常入力、shinki_flg=TRUE
- **9.0** 購読者情報と同じ
- **9.1** チェックの場合、No.27〜37を非活性化・入力したデータをクリア。DB保存時：購読者情報からコピー
- **9.2** 未チェックまたはチェック解除の場合：No.27〜37を活性化、No.27〜30、34〜37が必須となる
- **10.0** 支払方法による表示切り替え
- **10.1** 1:口座引落の場合→No.41〜49が必須
- **10.2** 2:現金集金、4:JA施設等、9:その他の場合→No.42〜49は任意
- **10.3** 3:振込集金、5:給与天引き、6:クレジットカードの場合は、46～49番の項目が必須
- **10.4** 支払方法が「振込集金」の場合、入金完了時に t_koza_furikae テーブルに1件のレコードを登録
- **11.0** 購読者層分類による切り替え
- **11.1** 農業者を選択する場合→No.51を表示（水稲/野菜/果樹/畜産/その他）

- **14.1** 購読者情報の登録・更新・解約などの操作に応じて、履歴テーブル（t_dokusya_rireki）のステータスフラグを適切に設定
- **14.2** フラグ設定ルール
  - 最新データフラグ（saishin_data_flg）
  - ・新規作成の履歴レコードはTRUEに設定
  - ・既存の最新レコードは FALSE に更新
  - ・TRUEとなっているdokusya_idは1件のみとする
  - 新規フラグ（shinki_flg）
  - ・新規登録時：TRUE
  - ・再読時：TRUE
  - ・通常更新時：FALSE
  - ・解約時：FALSE
  - 解約フラグ（kaiyaku_flg）
  - ・解約処理時：TRUE
  - ・その他の場合：FALSE
  - 増減報告フラグ（zougen_hokoku_flg）(販売店変更・住所変更・新規登録・解約)
  - ・購読部数などの変更がある場合：TRUE
  - ・変更がない場合：FALSE
  - 処理フロー
  - 1. 最新レコード（saishin_data_flg = TRUE）を取得
  - 2. 既存レコードのsaishin_data_flgをFALSEに更新
  - 3. 入力内容および業務イベントに応じて各フラグを判定
  - 4. 新しい履歴レコードを作成（rireki_no +1）
  - 5. 各フラグを設定して登録
  - ケース別フラグ設定例
  - ● 新規登録
  - フラグ
  - saishin_data_flg
  - shinki_flg
  - kaiyaku_flg
  - zougen_hokoku_flg
  - ● 通常更新
  - フラグ
  - saishin_data_flg
  - shinki_flg
  - kaiyaku_flg
  - zougen_hokoku_flg
  - ● 解約
  - フラグ
  - saishin_data_flg
  - shinki_flg
  - kaiyaku_flg
  - zougen_hokoku_flg
  - 補足
  - ・履歴テーブルは追記専用（UPDATEしない）
  - ・フラグは業務イベントに応じて必ず設定
  - ・不整合防止のためトランザクション制御を行う

  - ・データ取得成功の場合 → フォームにデータを反映
  - ・データ取得失敗の場合→ ACSMS-MSG-011-016 を表示
  - ・権限なしのアカウントの場合 → ACSMS-MSG-011-017 を表示
  - 購読者IDは変更不可とする。
- **15.2** 登録処理の前に、入力チェック・バリデーションチェックを行う。
  - ・エラーの場合、該当項目の下にエラーメッセージを表示
  - ・更新成功の場合、ACSMS-MSG-011-015を表示し、「購読者明細検索画面」へ戻る
- **15.3** データ更新ロジック
  - 既存レコードの上書き（物理更新）ではなく、新しい履歴番号でのレコード追加を行う。
  - ・ステップ1：旧レコードの無効化
  - ‣対象の購読者IDに紐づく、現在「最新データフラグ = true」となっている既存レコードのフラグを false に更新
  - ・ステップ2：履歴番号の採番
  - ‣対象の購読者IDの最大履歴番号を取得し、それに「1」を加算した値を新しい履歴番号とする
  - ・ステップ3：新規レコードの挿入
  - ‣画面で編集された最新の情報を、新しいレコードとしてテーブルに挿入
  - ‣その際、以下の項目をシステム側で自動設定する：
  - ▼履歴番号: ステップ2で採番した値
  - ▼最新データフラグ: true
  - ▼ユーザID: ログイン中のユーザーID
  - ▼更新日時: システム時刻（現在）
