#### 14. ステータスフラグ制御

- **14.1** 購読者情報の登録・更新・解約などの操作に応じて、履歴テーブル（t_dokusya_rireki）のステータスフラグを適切に設定する。
- **14.2** フラグ設定ルール：
  - 最新データフラグ（saishin_data_flg）
  - ・新規作成の履歴レコードはTRUEに設定する。
  - ・既存の最新レコードは FALSE に更新する。
  - ・TRUEとなっているdokusya_idは1件のみとする。
  - 新規フラグ（shinki_flg）
  - ・新規登録時：TRUE
  - ・再読時：TRUE
  - ・通常更新時：FALSE
  - ・解約時：FALSE
  - 解約フラグ（kaiyaku_flg）
  - ・解約処理時：TRUE
  - ・その他の場合：FALSE
  - 増減報告フラグ（zougen_hokoku_flg）
  - ・購読部数（販売店変更・住所変更・新規登録・解約）の変更がある場合：TRUE
  - ・変更がない場合：FALSE
- **14.3** 適用日と履歴（顧客要件 2026-07 改訂：販売店・支払方法の変更日を廃止し、適用日は読者情報変更適用日(`joho_henko_tekiyo_date`)に統一。**画面編集は1更新1レコード**）。
  - 販売店・支払方法を含むすべての変更は、単一の適用日 `joho_henko_tekiyo_date`（ユーザー入力・未来日のみ）で**1件の履歴行**として記録する（販売店・支払方法専用の適用日列は持たない）。
  - 旧仕様（2026-06）の「情報変更イベントと販売店変更イベントに分割し適用日順に2件記録」は画面編集では**廃止**。同一フォーム送信で情報・販売店の両方が変わっても履歴は1件のみ。
  - 追加レコードを `saishin_data_flg` は当日基準の再計算（recomputeMaster）で確定する（未来日運用のため到来日まで master は変わらない）。`zenkai_*`・`zougen_hokoku_flg` は「直前行 → 当該行」の差分で算出する。
  - 注：Excel一括取込（SCR-016）も v1.3（2026-07）で本ロジックに統一済み（UPDATE は1更新1レコード・適用日は `joho_henko_tekiyo_date`）。解約予約（購読中止日入力）は別の「解約」履歴行として1件挿入する（不変）。
  - 処理フロー
  - 1. 最新レコード（saishin_data_flg = TRUE）を取得する。
  - 2. 既存レコードのsaishin_data_flgをFALSEに更新する。
  - 3. 入力内容および業務イベントに応じて各フラグを判定する。
  - 4. 新しい履歴レコードを作成する。（rireki_no +1）
  - 5. 各フラグを設定して登録する。
  - ケース別フラグ設定例
  - ● 新規登録
  - フラグ
  - saishin_data_flg
  - shinki_flg
  - kaiyaku_flg
  - zougen_hokoku_flg
  - ● 通常更新
  - フラグ
  - saishin_data_flg
  - shinki_flg
  - kaiyaku_flg
  - zougen_hokoku_flg
  - ● 解約
  - フラグ
  - saishin_data_flg
  - shinki_flg
  - kaiyaku_flg
  - zougen_hokoku_flg
  - 補足
  - ・履歴テーブルは追記専用（UPDATEしない）
  - ・フラグは業務イベントに応じて必ず設定する。
  - ・不整合防止のためトランザクション制御を行う。

#### 15. 購読者情報更新（編集モード）

- **15.0** 参照モード → 編集モード選択（当日変更 / 予約変更・顧客要件2026-07）
  - 検索結果一覧から編集画面へ遷移した直後は、**参照モード（全項目 read-only）** で表示する。右上に「**当日変更**」「**予約変更**」ボタンを表示し、編集する場合はモードを選択させる。
  - **当日変更モード**：情報変更適用日を**本日に固定**（入力不可）。**即時反映可能な項目のみ**入力可とする。
    - 対象項目（当日反映可）：支店、組合員コード、単価、購読者名、メールアドレス、生年、性別、配達先連絡先1／2、配達先氏名、郵送区分、支払方法、購読料支払サイクル、引落口座番号、引落口座名義、読者属性、主な生産物（農業者の場合）、備考。
    - **帳票に影響する項目は当日反映不可**（グレーアウト）：購読部数、購読者住所、販売店コード、配達先住所、購読中止日。これらは予約変更で行う。
    - **紙版**は上記制限を受ける。**電子版**は紙の帳票を生成しないため、当日変更でも**全項目**入力可とする（帳票影響項目の制限なし）。
  - **予約変更モード**：情報変更適用日の初期値は**空欄（必須入力・未来日のみ）**。当日変更で入力可能な項目に加え、**購読部数・購読者住所・販売店コード・配達先住所・購読中止日**も入力可とする。
  - **モード切替**（当日変更 ⇄ 予約変更）は、**一度入力内容をリセット**してからモードを切り替える（確認ダイアログ）。
  - **電子版（購読種別=2）の制限**：参照モードで開く導線・モード選択ボタンの表示は**紙版と同一**とするが、**「予約変更」ボタンは非活性（グレーアウト）** とし、当日変更のみ選択可とする。ボタンを**非表示にはしない** — 隠すと「この画面に予約変更機能が無い」と誤読され、紙版との違いが画面から伝わらないため。非活性の理由は参照モード時の補足テキスト「電子版は当日変更のみです（予約変更は使用できません）。」で示す。
  - **モード選択ボタンの非表示条件**：併読／電子版クレジットカード決済者（read-only）、承認待ち（承認/否認フロー）、解約済み読込（再購読フロー）、`dokusya.update` 権限なし。
  - **モードに入っただけでは変更扱いとしない**：当日変更を選ぶと適用日が本日に変わるが、これはモードの仕様であって業務変更ではない。業務項目を1つも変更せずに更新した場合は ACSMS-MSG-011-018（変更がありません。）を表示し、更新・履歴作成を行わない（予約変更も同様）。
  - サーバ側（BE）が境界を enforce する：当日変更で紙版が帳票影響項目を変更した場合は `VALIDATION_ERROR`。
- **15.1** 検索結果一覧の任意行をクリックすると、購読者情報登録画面（編集モード）へ遷移する。
  - 純粋な「電子版」のみの読者も本画面で編集可とする（顧客要件2026-07・上記15.0の当日変更＝全項目可）。併読／電子版クレジットカード決済者は参照のみ（Read-only）とする。

  - ・データ取得失敗の場合→ ACSMS-MSG-011-016 を表示する。
  - ・権限なしのアカウントの場合 → ACSMS-MSG-011-017 を表示する。
  - 購読者IDは変更不可とする。
- **15.2** 登録処理の前に、入力チェック・バリデーションチェックを行う。
  - ・エラーの場合、該当項目の下にエラーメッセージを表示する。
  - ・更新成功の場合、ACSMS-MSG-011-015を表示し、「購読者明細検索画面」へ戻る。
- **15.3** データ更新ロジック
  - 既存レコードの上書き（物理更新）ではなく、新しい履歴番号でのレコード追加を行う。
  - ・ステップ1：旧レコードの無効化
  - ‣対象の購読者IDに紐づく、現在「最新データフラグ = true」となっている既存レコードのフラグを false に更新する。
  - ・ステップ2：履歴番号の採番
  - ‣対象の購読者IDの最大履歴番号を取得し、それに「1」を加算した値を新しい履歴番号とする。
  - ・ステップ3：新規レコードの挿入
  - ‣画面で編集された最新の情報を、新しいレコードとしてテーブルに挿入する。
  - ‣その際、以下の項目をシステム側で自動設定する：
  - ▼履歴番号: ステップ2で採番した値
  - ▼最新データフラグ: true
  - ▼ユーザID: ログイン中のユーザーID
  - ▼更新日時: システム時刻（現在）
