## システム概要

本システムは、JA向けのクラウド型読者管理システムであり、購読者情報の管理、購読履歴の管理、口座振替データの管理などの機能を提供する。

主な機能として、購読者情報の登録・更新・検索、購読内容の変更履歴管理、口座振替データの作成および管理、ファイルのアップロード・ダウンロード機能、システムのお知らせ管理などを提供する。

また、ユーザーのログイン管理、ログイン履歴の記録、ユーザー操作ログの記録などのセキュリティ・監査機能をサポートする。

## ACSMS-TC-026-001 — 画面アクセス禁止（NICHINO_ADMIN）

- 観点ID: VP-A-01
- 種類: Abnormal (異常)
- 前提条件:
  - ・NICHINO_ADMIN でログイン済み（2段階認証済み）
  - ・権限「report.export_meibo」を持たない

### 手順

ステップ1：
ダッシュボードを開き、サイドバーに「購読者名簿出力」項目が表示されないことを確認

ステップ2：
ブラウザのアドレスバーに「/report/meibo」を入力し、直接アクセス

ステップ3：
DevToolsのNetworkタブでGET「/api/v1/report/meibo/preview」を有効なリクエストパラメータで送信

### 期待結果

ステップ1：
サイドバーに「購読者名簿出力」項目が表示されないこと

ステップ2：
トースト「アクセス権がありません。」が表示されること、かつ「/dashboard」へ遷移すること

ステップ3：
HTTPステータスコード403が返却されること（`error_code: FORBIDDEN`、メッセージ `この画面へのアクセス権限がありません。`）

補足：
・本画面の帳票出力APIで403を受領した場合、フロントエンドはメッセージ「この機能はJAアカウントのみ使用できます。」を表示すること（ACSMS-MSG-026-001）
・FEメニュー、FEルーターガード、BE APIガードの3層すべてでアクセスが制御されること

## ACSMS-TC-026-042 — 支店による絞込み（管理支店別のみ・任意条件）

- 観点ID: VP-C-08
- 種類: Normal (正常)
- 前提条件:
  - ・role: JA_HONTEN（ja_id=100・`report.export_meibo` 権限あり）
  - ・管理支店 A（kanri_shiten_id=10）配下に 支店 X（shiten_id=21）／支店 Y（shiten_id=22）が存在
  - ・管理支店 B（kanri_shiten_id=11）配下に 支店 Z（shiten_id=31）が存在
  - ・適用日時点で有効な購読者：支店 X に 3件、支店 Y に 2件、支店未設定（shiten_id が NULL）が 1件（いずれも管理支店 A 配下）

### 手順

ステップ1：
帳票種別に「販売店別購読者名簿」を選んだ状態で、支店の入力欄が表示されるか確認する

ステップ2：
帳票種別を「管理支店別購読者名簿」に切り替え、管理支店を未選択のまま支店の入力欄を操作する

ステップ3：
管理支店に A を選び、支店ドロップダウンを開いて候補を確認する

ステップ4：
支店を選ばずに「レポートプレビュー」を押す

ステップ5：
支店に X のみを選んで「レポートプレビュー」を押す

ステップ6：
支店に X を選んだ状態のまま、管理支店を A から B に変更する

ステップ7：
管理支店 A ＋ 支店 X の条件で「レポートデータExcel出力」を押す

### 期待結果

ステップ1：
支店の入力欄は表示されないこと（販売店別の帳票には支店列が無いため）

ステップ2：
支店の入力欄は表示されるが非活性で、「先に管理支店を選択してください」の案内が出ること

ステップ3：
支店 X と 支店 Y のみが候補に出ること。管理支店 B 配下の 支店 Z は出ないこと

ステップ4：
支店は任意条件のため検証エラーにならず、管理支店 A 配下の全 6件（支店未設定の1件を含む）が出力されること

ステップ5：
支店 X の 3件のみが出力されること。**支店未設定の1件は含まれない**こと

ステップ6：
支店の選択が自動で解除され（空になり）、候補が 支店 Z に入れ替わること

ステップ7：
プレビューと同じ 3件が Excel に出力され、`t_file_download` に登録されること

補足：
・支店 = 配達担当支店（`t_dokusya_rireki.shiten_id`）。銀行支店（`bank_shiten_id`）ではない
・`shiten_id` は購読者登録で任意項目のため NULL があり得る。**電子版連携で取り込んだ購読者は常に NULL**（電子版に配達担当支店の概念が無いため）。支店を1件でも選ぶと NULL の購読者は IN 比較が NULL となり対象外になる（ステップ5）
・一時期この支店条件を必須にしていたが、それだと NULL の購読者がどう操作しても名簿へ出せなかった（「全て」を選んでも実在する支店IDを列挙するだけで NULL は拾えない）ため任意へ戻した（顧客要件 2026-08 改訂）。ステップ4がその回帰確認
・管理支店を変えたときに支店の選択を持ち越さないのは、配下に無い支店で絞ったままだと結果0件になった理由が画面から読み取れないため
・販売店別で支店条件を出さないのは、帳票に支店列が無く絞込みの理由が紙面から読めないため。API 側も `report_type=hanbaiten` のときは `shiten_ids` を無視する
