### B. 機能詳細

- **1.0** 画面初期表示
- **1.1** アカウントマスタ登録画面へアクセスする時、以下のように表示
  - ・都道府県一覧を取得（GET /api/master/prefectures）
  - ・空フォーム表示：紙版=FALSE、電子版=FALSE、管理者区分=未選択
  - ・カスケードプルダウン（都道府県・JA・管理支店）はデフォルトで非表示
  - ・JA・管理支店プルダウンはデータ未読み込み（上位選択待ち）
- **1.2** 編集モード（一覧画面から遷移）
  - ・GET /api/accounts/:id でアカウントデータ取得
  - ・フォームにデータ反映：ログインID（読取専用）、カスケード、メール、名称、フラグ、備考
  - ・パスワードは空欄（変更時のみ入力）
  - ・カスケードを順番に読み込み：都道府県→JA→管理支店、その後既存値をセット
- **2.0** 新規アカウント登録
- **2.1** 「登録」ボタンを押す時に実行
  - ・必須項目チェック：ログインID、パスワード、管理者区分、アカウント名称。入力しない場合、ACSMS-MSG-025-001メッセージを表示
  - ・条件付き必須：都道府県（管理者区分=3,4,5時）、JA（管理者区分=3,4,5時）、管理支店（管理者区分=5時）。入力しない場合、ACSMS-MSG-025-001メッセージを表示
  - ・形式チェック：  ログインID（半角英数記号）、形式不正の場合、ACSMS-MSG-025-002メッセージを表示
  - ・予約名チェック：ログインIDが `SYSTEM` 単体または `SYSTEM_` 始まり（大文字小文字を区別しない）の場合は登録不可。「ログインIDに「SYSTEM」から始まる文字列は使用できません。」を表示。バッチの実行者名（SYSTEM_DENSHI_SYNC / SYSTEM_BATCH_NIGHTLY）と衝突すると、`t_dokusya_rireki.created_by` による「電子版同期由来の読者か」の判別が壊れるため（顧客要件 2026-08）
  - パスワード（8〜32文字、複雑性）。形式不正の場合、ACSMS-MSG-025-003メッセージを表示
  - メール（メール形式）。形式不正の場合、ACSMS-MSG-025-005メッセージを表示
- **2.2** サーバーにデータ送信
  - ・login_id重複チェック → ACSMS-MSG-025-004
- **2.3** 登録処理
  - ・m_accountにレコード作成。初期値: login_failure_count=0, account_lock_flg=FALSE mfa_enable_flg=false
  - ・登録成功の場合 → ACSMS-MSG-025-007を表示、システムエラーの場合→ ACSMS-MSG-025-008を表示
- **2.4** 一覧画面へ遷移
- **3.0** 前の画面に戻る
- **3.1** 「前の画面に戻る」ボタンを押下するときに実行
  - アカウント明細検索画面に遷移、入力したデータが保存されない
- **4.0** 管理者区分による表示変更
- **4.1** 管理者区分=1、2の場合、都道府県、JA、管理支店を非表示
- **4.2** 管理者区分=3の場合、都道府県、JAが入力必須
  - 管理者区分=4の場合、都道府県、JAが入力必須
  - 管理者区分=5:すべての項目が入力必須
- **5.0** カスケード — 都道府県選択
- **5.1** 都道府県を選択するたびに、JA・管理支店一覧を再取得
  - 管理者区分= 3の場合、都道府県コード　＋　「chuokai_flg=1」によって該当JA一覧を取得
  - 管理者区分= 4の場合、都道府県コード　＋　「chuokai_flg=0」によって該当JA一覧を取得
  - 管理者区分= 5の場合、 都道府県コード　＋　「chuokai_flg=0」によって該当JA一覧を取得
- **6.0** カスケード — JA選択
- **6.1** JAを選択するたびに、管理支店一覧を再取得
- **7.0** 電子版の取扱いチェック
- **7.1** 管理者区分=3,4,5の場合のみ必須チェック
- **7.2** チェック → denshi_flg=TRUE → OA紐付き → Web申込読者承認可能
- **7.3** 未チェック → denshi_flg=FALSE → 電子版読者の登録・解約・承認は不可
- **8.0** 更新画面（編集モード）
- **8.1** 検索結果一覧から任意の行を押下する時にアカウント登録画面（編集モード）に移動。
  - システムはIDでアカウントデータを取得
  - ・データ取得成功の場合 → フォームにデータを反映
  - ・データ取得失敗の場合→ ACSMS-MSG-025-006を表示
  - ・権限なしのアカウントの場合 → ACSMS-MSG-025-009を表示
  - ・編集時にパスワードを空欄のままにした場合、既存のパスワードを保持する。
  - ログインID項目は変更不可（disabled）で表示
- **9.0** 所属支店の設定と制限（顧客要件2026-07）
- **9.1** 所属支店（shiten_id）は管理者区分=5（JA管理支店）かつ管理支店選択済みのときのみ表示・設定可（任意）。管理支店を切り替えると所属支店はリセットし、配下の支店を再取得する。管理者区分=5以外で送信された shiten_id はサーバ側で破棄する。
- **9.2** 送信された所属支店は「選択した管理支店の配下」かつ「同一JA」であることをサーバ側で検証する（不正時は入力エラー）。
- **9.3** 制限①（購読者スコープ）: 所属支店を設定したアカウントは、当該支店（t_dokusya.shiten_id）の購読者のみ参照・編集・追加できる。購読者を表示・登録する全画面（購読者明細検索/購読者情報登録/Excel取込/販売店一括置換 等）に適用。新規/追加時は購読者の管理支店・支店をアカウントの所属支店に強制設定（画面上はグレーアウト）。
- **9.4** 制限②（帳票5画面の利用不可）: 所属支店を設定したアカウントは、口座振替データ出力(SCR-020)/配達手数料支払情報出力(SCR-021)/購読者名簿(SCR-026)/増減連絡票（販売店）(SCR-028)/増減通知（日本農業新聞）(SCR-029) を使用できない（アクセス時403、メニューは表示のうえ非活性=グレーアウト）。権限（ロール単位）は保持したまま、アカウント属性(shiten_id)ベースの実行時ガードで制御する。
- **9.5** 所属支店 未設定（NULL）のアカウントは従来通り管理支店単位のスコープで動作し、上記制限を受けない。

- **10.0** セキュリティ上重要な変更時のセッション破棄（2026-07）
- **10.1** セッションのペイロード（権限・ロール・所属スコープ）は**ログイン時に固定**され、リクエストごとに DB を再検証しない。したがってセッションを破棄しない限り、降格・ロック・所属変更が**既にログイン中の利用者へ反映されない**。
- **10.2** 次のいずれかを変更して更新した場合、対象アカウントの有効セッションを全て破棄し、再ログインを必須とする：**パスワード変更（管理者による強制リセット）／アカウントロック（ロックする方向）／管理者区分（ロール）の変更／所属（JA・管理支店・所属支店）の変更**。
- **10.3** 次の場合は破棄しない：**ロック解除**（解除操作で管理者自身のセッションを切らないため）／氏名・メールアドレス・備考のみの変更。
- **10.4** アカウント削除時は無条件に全セッションを破棄する。
- **10.5** 破棄は更新の確定後に行う。破棄処理が失敗しても更新自体は成立しているため、画面には成功メッセージを表示する（セッションはいずれにせよ 24 時間で失効する）。
