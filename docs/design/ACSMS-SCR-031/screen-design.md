### B. 機能詳細


#### 1. 初期表示

- **1.1** 初期表示は新規モードでフォームを表示 → GET API を呼び出し、お知らせ一覧を取得（日農管理者のみお知らせを登録・編集可能）
  - ・権限なしのアカウントの場合、ACSMS-MSG-031-006を表示
- **1.2** フォームの全項目が空欄の状態で表示され。フォームヘッダーに「新規登録」テキストが表示され

#### 2. 新規登録

- **2.1** 「保存」ボタンをクリックすると、バリデーションチェックを実行
  - ・お知らせタイトル：必須、最大200文字→ 入力しない場合、ACSMS-MSG-031-011メッセージを表示。
  - ・公開場所：必須、`m_code.code_category='PUBLISH_LOCATION'` を参照（1:ログイン画面, 2:メニュー画面, 3:メニュー画面（締め切り時間））→ 選択しない場合、ACSMS-MSG-031-011メッセージを表示。ラジオは常に 1 / 2 / 3 の3択を表示する。お知らせ種別ドロップダウンは選んだ公開場所に応じて絞り込まれる（顧客確認 2026-05）：
    - 公開場所 = 1 または 2 → 種別は {1: システム, 2: 重要, 3: 一般} のみ選択可。
    - 公開場所 = 3（メニュー画面（締め切り時間））→ 種別は {4: 締め切り時間} のみ。watcher により公開場所=3 を選んだ瞬間に種別=4 を自動セット、公開場所=3 から外れた瞬間に種別を未選択へ戻す。
    - 編集モードで読み込んだレコードが type=4 の場合、公開場所ラジオも種別ドロップダウンも read-only として 4↔3 のペアリングを変更不能にする（型=4 削除不可と同ポリシー）。
    - BE 側でも `assertDeadlineLocationPairing` で type=4 ⇔ publish_location=3 を検査し、API 直接呼び出しを遮断する。
  - ・状態：必須、（1, 2または 3）→ 選択しない場合、ACSMS-MSG-031-011メッセージを表示。
  - ・表示開始日（開始日時）：必須、有効な日時のチェック（yyyy/MM/dd HH:mm形式）、開始<=終了の相関チェック。過去日時チェックは「分」精度で行う（顧客確認 2026-05）：
    - 新規作成時：現在分より前の日時は選択不可。FE は `:disabled-date`／`:disabled-time` で picker 操作を抑止し、`validateForm` でも検証。BE は `service.create` でも検証する。エラー `過去日は選択できません。`。
    - 編集モード + 保存済み開始日時が現在分より前：開始日ピッカーを read-only として表示（FE 側 UI）。BE は値変更を一切受け付けない（攻撃者の改竄を遮断）。
    - 編集モード + 保存済み開始日時が現在分以降：変更可能。ただし新しい値は現在分以降であること。FE / BE どちらでも検証。
    - エラー形式（BE）：HTTP 400 `VALIDATION_ERROR` + `errors: [{ field: "publish_start_date", message: "過去日は選択できません。" }]`。
  - ・表示終了日：任意、有効な日時のチェック（yyyy/MM/dd HH:mm:ss形式）、開始<=終了の相関チェック→エラーの場合、ACSMS-MSG-031-008メッセージを表示
  - ・お知らせ種別：必須 → 選択しない場合、ACSMS-MSG-031-011メッセージを表示。
  - ・お知らせ種別＝「締め切り時間」のレコードはシステム全体で1件のみ許容する（顧客確認 2026-05）。`publish_location` の値に関わらず、既に締め切り時間タイプのレコードが存在する場合は、新規作成は不可とし、編集のみ可能とする。重複時はエラーメッセージ `公開場所「メニュー画面」かつ種別「締め切り時間」のお知らせが既に存在するため登録できません。`（`DEADLINE_NOTICE_DUPLICATE`、HTTP 400）を返却する。
  - ・内容：必須、最大2000文字、空不可→ 入力しない場合、ACSMS-MSG-031-011メッセージを表示。
- **2.2** エラー発生の場合 → 該当フィールド下にエラーメッセージを表示。
- **2.3** バリデーションチェックOKの場合 → レコードを新規作成。
- **2.4** 処理結果：
  - ・保存成功の場合 → 一覧再読込、保存された行をハイライト表示、保存した内容を保持し、編集モード（編集中ID表示）とし、ACSMS-MSG-031-001表示
  - ・システムエラーの場合 → ACSMS-MSG-031-007を表示。

#### 3. 編集読込

- **3.1** 一覧の「編集」ボタンをクリックすると、行をハイライト表示
  - ・未保存の変更がある場合 → ACSMS-MSG-031-010警告ダイアログを表示
  - 「編集を続行」 → 何もせず元の状態を保持
  - 「破棄して続行」ボタンを押下する場合 → 3.2の処理へ
  - ・未保存の変更がない場合 → 直接以下の処理へ
- **3.2** 選択行のデータをフォームの全フィールドに反映。
- **3.3** 編集モードへ切り替え、編集フォーム上部に「編集中：お知らせID」を表示

#### 4. 更新（編集モード）

- **4.1** 編集内容を入力して、「保存」ボタンをクリックすると、バリデーションを実行（ステップ2.1と同様。編集モード時、開始日が過去日の場合は変更不可（読み取り専用）で表示、開始日が未来日の場合は本日以降の日付に変更可能）
- **4.2** バリデーションNGの場合 → 該当フィールド下にエラーメッセージを表示。
- **4.3** バリデーションOKの場合 →ID に基づいてレコードを更新
- **4.4** 処理結果：
  - ・更新成功の場合 → 一覧再読込、保存行ハイライト維持、編集モード維持、ACSMS-MSG-031-002表示、未保存の変更なし
  - ・システムエラーの場合 → ACSMS-MSG-031-007を表示。
- **5.0** 削除
- **5.0.1** 締め切り時間（oshirase_type=4）のレコードは削除不可（顧客確認 2026-05、1件のみ運用される締め切り時間データの取り違え／消失防止）。一覧の操作列では「削除」をリンクではなく非活性スタイルの `<span>` として表示する。BE 側でも `service.remove` で `oshirase_type=4` を検出した場合 HTTP 400 `BAD_REQUEST`（メッセージ `締め切り時間のお知らせは削除できません。`）を返す。
- **5.0.2** 編集モードで type=4 レコードを開いた場合、「お知らせ種別」セレクトを read-only として表示し、種別変更を禁止する。
- **5.1** 操作列の「削除」ボタンをクリックすると、対象お知らせが関連テーブルに紐づいているか確認。
- **5.2** 紐づいている場合 → ACSMS-MSG-031-005 を表示。削除不可。
- **5.3** 紐づいていない場合、確認ダイアログ（ACSMS-MSG-031-003）を表示。
  - 「はい」をクリックした場合：
  - ・システムは論理削除を実行（deleted_at = NOW()）
  - ・成功メッセージ（ACSMS-MSG-031-004）を表示
  - ・一覧を再読込
- **5.4** 「いいえ」をクリックした場合 → ダイアログを閉じ、何もしない。
- **5.5** システムエラーの場合 → ACSMS-MSG-031-007を表示。
- **6.0** ページネーション
- **6.1** 表示ページを切り替える時、以下のように処理
  - ・未保存のデータがある場合 → ACSMS-MSG-031-010警告ダイアログを表示
  - 「破棄して続行」 → 未保存のデータを破棄し、次のページのデータを取得
  - 「編集を続行」 → 何もせず、現在の状態を保持
- **6.2** ・デフォルト：20件/ページ
  - ・最大：100件/ページ
