# 非機能要件

| カテゴリ | 項目 | 要件内容 | 補足・根拠 |
| --- | --- | --- | --- |
| 性能・可用性 | 応答速度 | 低速度回線（1Mbps以下）でも問題なく動作すること | JA農村部での低速回線環境を考慮 |
| 性能・可用性 | 同時利用ユーザ数 | JA担当者100名が同時に利用してもシステムが安定して動作すること | |
| 性能・可用性 | スケーラビリティ | 利用者数の増加に応じてサーバのスペックアップ・ダウンに対応できること | AWSのオートスケーリング等を活用 |
| 性能・可用性 | 可用性 | 年間稼働率99%以上を目標とする（年間総ダウンタイム：87.6時間以内）<br>障害発生時は即時復旧できる体制を整えること | |
| セキュリティ | アクセス制御 | ユーザごとに役割（日農・中央会・JA本店・JA支店）に応じたアクセス権を設定できること | アカウントの考え方シート参照 |
| セキュリティ | 認証 | ID・パスワードによる認証を必須とし、必要に応じて多要素認証（MFA）にも対応すること | |
| セキュリティ | データ保護 | 購読者情報・口座振替情報など個人情報は暗号化して保存・送信すること<br>不正アクセスや情報漏洩を防止するための対策を講じること | 個人情報保護法準拠 |
| セキュリティ | 監査ログ | ユーザの操作履歴を記録し、必要時に参照できること | ログ参照画面にて対応 |
| セキュリティ | 法規制対応 | 個人情報保護法および関連法令に準拠した設計・運用を行うこと | |
| 拡張性・保守性 | 拡張性 | 将来的な利用者数の増加・機能追加に柔軟に対応できる設計とすること | 2次開発（併読管理等）を見据えた設計 |
| 拡張性・保守性 | バックアップ | 毎日データバックアップを実施し、災害時等にもデータ復旧が可能な体制を整えること | |
| 拡張性・保守性 | 保守性 | システムのバージョン管理・バックアップ体制を整え、障害時やアップデート時に迅速対応できること<br>システムの運用・保守マニュアルを作成すること | 成果物として保守マニュアルを含む |
| 操作性・ユーザビリティ | 操作性 | 直感的で分かりやすい画面設計とすること<br>デジタルスキルが高くなくても扱えること | |
| 操作性・ユーザビリティ | ヘルプ機能 | 操作マニュアルやFAQを画面内から参照できること | |
| システム連携 | OAシステム連携 | OAシステムへ連動するためのCSVファイルをクラウド上に作成すること<br>将来的なOAシステム自動連動に備えた設計とすること | 現フェーズは電子帳票案を採用 |
| システム連携 | 電子版読者管理システム連携 | 電子版読者管理システムと双方向でデータ連携できること<br>データ連動エラーが発生した場合、アラート通知を行うこと | |
| システム連携 | 口座振替データ出力 | 口座振替データをテキスト（全銀フォーマット）、エクセルデータで出力できること。 | |
| システム連携 | 帳票出力 | 帳票はPDFで出力でき、プリンターで印刷できること | |
