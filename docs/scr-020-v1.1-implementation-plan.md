## 1. 前提と設計判断（未確定は要顧客確認 ⚠️）

現行は **1 ショット**（作成開始 = 即ファイル出力）。新仕様は **2 ステップ**:
`作成開始 → プレビュー表示 → 金額編集 → ファイル作成 → ダウンロード`。

計画を具体化するため以下を暫定決定する（各項は §7 で顧客確認）。

| # | 論点 | 暫定決定（計画の前提） |
|---|---|---|
| D1 | フィルタ変更でプレビュー破棄？ | **する**。プレビュー表示後に 年月日/管理支店/支店/口座支店 を変更したら `previewed=false` にして「作成開始」の再実行を要求。古いプレビューでファイル作成させない。 |
| D2 | 金額 = 0 の扱い | **許可**（Zengin は 0 可）。負数不可。0 の行も出力対象に残す。 |
| D3 | 金額の上限 | **0 〜 9,999,999,999（半角数字10桁・整数）**。Zengin データレコードの引落金額桁数に一致。 |
| D4 | 件数が多い JA | プレビューは **全件を1レスポンス**で返す（購読者数=数百想定）。FE は `a-table` クライアントページングで表示、ファイルは全件。将来サーバページング化は別途。 |
| D5 | プレビュー〜作成の間にデータ変化 | ファイル作成時に **再集計（スコープ）** し、`dokusya_id` で金額オーバーライドを突合。スコープに無い client 行は破棄、client に無いスコープ行は DB 金額を採用。 |
| D6 | 編集金額の保存先 | `t_koza_furikae.furikae_kingaku` のみ（スナップショット）。**m_tanka は不変**。 |
| D7 | 貯金種目 fallback `'1'` | **維持**（m_shiten 未取得時の安全値。UI デフォルト表記のみドキュメントから削除）。 |
| D8 | 必須チェックのタイミング | **作成開始**: 年月日・引落日 のみ必須（集計に必要）。**ファイル作成**: JASTEM 全項目 + 金額 を必須/形式チェック。 |

セキュリティ上の必須事項（`security.md` Layer2/4）: **export は client 送信の `dokusya_id` を信用しない**。必ず `session.ja_id` / `kanri_shiten_id` でスコープ再集計し、その集合にある行だけ金額を上書きする。

## 2. アーキテクチャ（2 エンドポイント）

```
① GET  /api/v1/koza-furikae/initial   (既存・変更なし)  JASTEM 初期表示
② POST /api/v1/koza-furikae/preview   (新規 API-020-003) 集計してJSON一覧を返す。DB/S3書込なし。
③ POST /api/v1/koza-furikae/export    (既存・改修 API-020-002) 編集金額を受け取り、
                                                            再集計+上書き→全銀CSV→S3+DB+監査
```

- ②③ とも集計ロジック `aggregate(body, session)` を共有（唯一の真実源）。
- ② 0 件 → `404 NO_TARGET_DATA`（MSG-020-002 をプレビュー段で表示）。
- ③ は blob 返却（現行どおり）。監査ログ・t_koza_furikae upsert は現行の atomic トランザクションを維持。

### 3.2 Service — `koza-furikae.service.ts`

1. **抽出**: 現行 `fetchAggRows` を `private aggregate(body, session)` に整理（preview/export 共用）。`KOZA_FURIKAE_AGG_SQL` は変更なし。
2. **新規** `previewData(body: PreviewKozaFurikaeDto, session)`:
   ```ts
   const rows = await this.aggregate(body, session);
   if (rows.length === 0) throw new NoTargetDataException(); // MSG-020-002
   return paginate(rows.map(toKozaPreviewRow), rows.length, 1, rows.length);
   //   ↑ 全件1ページ。meta.total を件数表示に使う。合計金額は別途 meta 拡張 or FE 集計。
   ```
   - **DB/S3 書込なし**、監査ログもなし（閲覧のみ）。
3. **改修** `exportCsv(body: ExportKozaFurikaeDto, session, req)`:
   ```ts
   const rows = await this.aggregate(body, session);          // スコープ再集計（信頼源）
   if (rows.length === 0) throw new NoTargetDataException();
   const override = new Map(body.rows.map(r => [Number(r.dokusya_id), r.furikae_kingaku]));
   for (const r of rows) {
     const ov = override.get(Number(r.dokusya_id));
     if (ov != null) r.furikae_kingaku = ov;                  // スコープ内のみ上書き
   }                                                          // client の不明 dokusya_id は無視
   // 以降は現行どおり: buildZenginFixed → iconv → fileArchive.archive
   //                → transaction( upsert t_koza_furikae(編集金額) + audit )
   ```
   - **セキュリティ**: `override` は突合のみ。client 行を直接ループしない → cross-tenant / 偽 dokusya_id 混入不可。
   - t_koza_furikae upsert は `r.furikae_kingaku`（編集後）を使う（D6）。

4. **新規** `koza-furikae.mapper.ts`（純関数）:
   ```ts
   export interface KozaPreviewRow {
     dokusya_id: number;
     koza_meigi: string;            // 預金者名（カナ）

     bank_branch_name: string;

     hikiotoshi_koza_no: string;    // ※表示。監査ログは現行どおりマスク
   ```

## 4. Frontend 実装計画

### 4.1 API wrapper — `api/koza-furikae/koza-furikae.ts`

```ts
export interface KozaPreviewRow {
  dokusya_id: number; koza_meigi: string; kanri_shiten_id: number | null;
  bank_branch_code: string; bank_branch_name: string;
  hikiotoshi_yokin_shubetsu: number | null; hikiotoshi_koza_no: string;
  furikae_kingaku: number;
}
export interface KozaPreviewEnvelope { data: KozaPreviewRow[]; meta: { total: number } }

export async function previewKozaFurikae(body: PreviewKozaFurikaeBody): Promise<KozaPreviewEnvelope> {
  const res = await axiosInstance.post('/api/v1/koza-furikae/preview', body);
  return res.data;
}
// ExportKozaFurikaeBody に追加:
//   rows: Array<{ dokusya_id: number; furikae_kingaku: number }>
```
0 件は BE 404 → 既存 `exportKozaFurikae` と同じく `{ error_code:'NO_TARGET_DATA' }` に正規化して再スロー（preview 側も同様のガードを付ける）。

### 4.2 View — `views/koza-furikae/KozaFurikaeExportView.vue`

**状態機械**
```
idle ──作成開始(年月日/引落日 validate)──▶ previewing ──成功──▶ previewed(編集可)
                                                    └─0件─▶ idle + MSG-020-002
previewed ──フィルタ変更──▶ idle（previewed=false, previewRows=[]）      ← D1
previewed ──ファイル作成(JASTEM+金額 validate)──▶ creating ──▶ done(ダウンロード + MSG-020-001)
```

**追加 state / ロジック**
```ts
const previewRows = ref<KozaPreviewRow[]>([]);
const previewed = ref(false);
const previewing = ref(false);
const noDataMessage = ref(false);

// 作成開始（＝プレビュー）
async function onPreview() {
  if (!validateForPreview()) return;           // 年月日・引落日 のみ
  previewing.value = true; noDataMessage.value = false;
  try {
    const res = await previewKozaFurikae(buildPreviewBody());
    previewRows.value = res.data; previewed.value = true;
  } catch (err) {
    if ((err as any)?.error_code === 'NO_TARGET_DATA') { noDataMessage.value = true; previewed.value = false; }
  } finally { previewing.value = false; }
}

// ファイル作成
async function onCreate() {
  if (!validateForCreate()) return;            // JASTEM 全項目 + 金額
  submitting.value = true;
  try {
    const { blob, filename } = await exportKozaFurikae({
      ...buildBody(),
      rows: previewRows.value.map(r => ({ dokusya_id: r.dokusya_id, furikae_kingaku: r.furikae_kingaku })),
    });
    downloadBlob(blob, filename ?? `口座振替データ_...csv`);
    notify.success('口座振替データの作成が完了しました。');   // MSG-020-001
  } catch (err) {
    if ((err as any)?.error_code === 'NO_TARGET_DATA') message.warning('対象データがありません。');
  } finally { submitting.value = false; }
}

// D1: フィルタ変更でプレビュー破棄
watch(
  () => [formState.target_month, formState.kanri_shiten_ids, formState.shiten_ids, formState.koza_shiten_ids],
  () => { if (previewed.value) { previewed.value = false; previewRows.value = []; } },
  { deep: true },
);
```

**UI 追加**
- **金額編集テーブル**（previewed 時のみ表示）: `<a-table :data-source="previewRows">`。金額列は
  ```vue
  <a-input-number v-model:value="record.furikae_kingaku" :min="0" :max="9999999999" :precision="0" />
  ```
  他列（氏名/引落支店/預金種目/口座番号）は表示のみ。合計金額行を footer に出す。
- **ボタン**: `作成開始`（常時活性・年月日必須）/ `ファイル作成`（`previewed && previewRows.length>0` の時のみ表示、`submitting` で loading）。左寄せ・primary 左（`vue.md` フッタ規約）。
- `preventEnterImplicitSubmit` は維持。金額入力での Enter 誤送信を防ぐ。

**バリデーション分割**（D8）
- `validateForPreview()`: 年月日・引落日 の必須のみ。
- `validateForCreate()`: 既存 JASTEM 必須+形式 に加え、`previewRows` 各行 `furikae_kingaku` が `0..9999999999` 整数。範囲外は該当行をハイライト or トップにメッセージ。

### 4.3 FE テスト（`__tests__/KozaFurikaeExportView.spec.ts` 追記）

- 作成開始 → previewKozaFurikae 呼び出し・テーブル描画・件数/合計表示

```
         1. wrapper spec + previewKozaFurikae / rows 追加
         2. view spec（2ステップ・編集・0件・フィルタ破棄）+ View 改修
         3. vue-tsc + npm test（frontend）
Phase 3  ドキュメント最終化（§6）＋ testcase.md 追記＋画面イメージ差し替え
Phase 4  結合スモーク（作成開始→編集→ファイル作成→媒体名 ZENOUTFD 確認）
```
